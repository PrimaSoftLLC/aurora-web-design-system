# Линтер

Система поставляет собственные правила stylelint. Это не украшение процесса:
пункты «ни одного литерального цвета», «размеры в px», «свой `:focus` не
рисуем» из [ADOPTION.md](ADOPTION.md) невозможно удержать на ревью — в
трёхсотстрочном дифе литерал не виден. Либо это проверяет машина, либо это не
правило, а пожелание.

Правила и опции — [lint/README.md](lint/README.md). Здесь только то, что нужно
знать владельцу системы и тимлиду приложения.

## Что проверяется

| Правило | Что ловит |
|---|---|
| `aurora/known-token` | `var(--ds-…)` на несуществующий токен; объявление своих `--ds-*` |
| `aurora/no-literal-color` | hex, `rgb()`, `hsl()`, `oklch()`, именованные цвета |
| `aurora/no-rem` | `rem` вместо `px` |
| `aurora/focus-from-tokens` | свой `outline` / `box-shadow` в состоянии фокуса, `outline: none` |
| `aurora/shadow-token-only` | `box-shadow` мимо ступеней системы |
| `aurora/no-deprecated-token` | устаревшее имя-алиас (список `aliases` в `lint/naming.config.json`); предупреждение, не ошибка |

Отдельно от stylelint работает проверка имён самих токенов —
`node lint/scripts/check-names.js`, часть `npm test` системы. Она читает
`tokens.json` и сверяет имена с [NAMING.md](NAMING.md): форма, лестницы
ступеней, четвёрки слотов статуса, уникальность. Это проверка для системы, а не
для приложений: токен, названный мимо грамматики, не доезжает до релиза.

## Почему внутри пакета системы

Список имён токенов собирается из `tokens.json` — того же файла, из которого
генерируется `tokens.css`. Значит, версия линтера всегда равна версии токенов,
которые стоят в приложении. Переименование токена в мажоре автоматически
становится ошибкой сборки у всех потребителей; рассылать ничего не нужно, и
линтер физически не может проверять вчерашний инвентарь.

Если бы правила жили отдельным пакетом, версии разъехались бы за месяц, и
линтер начал бы врать — а линтер, который врёт, отключают целиком.

## Подключение в приложении

```json
{ "extends": "@nikolaynn/design-system/stylelint-config" }
```

Дальше `npm run lint:css` в CI рядом с тестами. Подробности и SCSS-синтаксис —
в [lint/README.md](lint/README.md).

Новое приложение включает линтер в первый день, до первого экрана. Существующее —
на срезе 1 из [ADOPTION.md](ADOPTION.md), когда цвета уже переведены на токены:
раньше он покажет тысячи ошибок и будет отключён в тот же день.

## Чего линтер не проверяет

Литералы в TypeScript (конфиги ECharts — главный канал, через который цвета
просачиваются мимо SCSS), inline `[style]` в шаблонах Angular, глубокие импорты
внутренностей пакета. Это ESLint-слой, его пока нет.

И он ничего не знает про роль токена: `color: var(--ds-surface)` — формально
валидно, содержательно ошибка. Это видит только ревьюер, и ради этого приёмка
по-прежнему существует.
