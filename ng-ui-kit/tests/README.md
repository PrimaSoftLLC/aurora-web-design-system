# Проверки Angular

## Unit-тесты библиотеки и нового сайта

Используются стандартные Angular CLI 19, Karma/Jasmine и TestBed. Тесты *.spec.ts
находятся рядом с исходниками и импортируют их напрямую. Предварительная сборка
дизайн-системы, библиотеки и сайта для unit-тестов не требуется.

Из корня репозитория:

```sh
npm run test:angular
npm run test:site-angular
```

Обычные параметры Angular CLI:

```sh
npm run test:angular -- --include="src/components/checkbox/**/*.spec.ts"
npm run test:angular -- --watch
npm run test:angular -- --code-coverage
npm run test:site-angular -- --code-coverage
```

По умолчанию — один прогон в ChromeHeadless. Параметры test-target находятся
в angular.json и tsconfig.spec.json соответствующей папки. Можно использовать
прямой ng test из этой папки. Небольшой tools/test-unit.mjs только выбирает папку
и браузер; он не реализует собственный тестовый раннер или компиляцию.
Учитывается CHROME_BIN, установленный Chrome и существующий Playwright Chromium в CI.

Только тестовый tsconfig.spec.json сайта сопоставляет публичный Angular-импорт
исходному core.ts библиотеки; dev/production-импорты не менялись. Unit-spec исключены
из сборки библиотеки. Прежние JS-unit-тесты и ручное jsdom-окружение удалены.
Зависимость jsdom оставлена для прежних проверок репозитория.

Отчёты покрытия: ng-ui-kit/coverage/ui-kit/ и
documentation-site/coverage/documentation-site/. Они исключены из Git.
Показатели относятся к коду, загруженному unit-тестами; это не 100% покрытия
всей библиотеки или сайта. Обязательный порог не установлен.

## Существующие интеграционные проверки

Браузерные проверки сайта и установленных Angular-потребителей сохранены
в прежних файлах и прежнем процессе запуска. Они проверяют поставку, реальные
формы, клавиатуру, фокус, геометрию и доступность. Новых браузерных запускателей,
кеширования и отдельных файлов на каждый компонент не добавляется.

Form field/dsInput проверяются общим примером `consumers/shared/form-field-demo.*`,
который копируется в независимые приложения Angular 19.2.25 и 20.3.34. Он импортирует
только публичный вход установленного tarball; алиасов на исходники библиотеки нет.
Временные приложения создаются вне репозитория, чтобы Node не подхватывал
его родительские node_modules. Размер поля сравнивается с опубликованным токеном
`--ds-field-h`, а не с размерами кнопки или вручную скопированным числом.
Проверка `assertAngularFormField` находится в существующем tools/check-angular.mjs
и вызывается общим check:angular. Она проверяет нативный ввод, number/null, Reactive
Forms, ngModel, touched, ошибки, disabled/readonly, reset, проекцию, ARIA, maxRows
и стили четырёх режимов. Это интеграционный пример приложения, а не замена unit-spec.
Новых npm-команд, зависимостей или отдельного JS-раннера для Form field нет.

Полный npm run verify по-прежнему объединяет существующие проверки. В него
добавлены только два Karma-шага: angular-unit и documentation-site-unit.
Самостоятельный запуск unit-тестов не означает прохождение полного verify.
React и старый сайт этой работой не перерабатываются.

Текущие результаты — в [статусе](../../docs/plans/angular-ui-kit-status.md).
