Таблица системы: граница вместо полос, сортировка в заголовке, выбор строк, моно-столбцы, высота строки из плотности.

**Потребитель задаёт** `columns` и `rows`, при необходимости `rowKey`, выбор (`selectable`, `selectedIds`, `onToggleRow`, `onToggleAll`), сортировку (`sortKey`, `sortDir`, `onSort`), `activeId` и `onRowClick`, `stickyHeader`, `empty`, `footer`. Родитель даёт таблице высоту — она заполняет flex-контейнер.

- Сортировка одна и всегда задана: заголовок — настоящая кнопка, цикл «по возрастанию ⇄ по убыванию», без «несортированного» шага. `sortable` ставьте только на столбец, по которому источник данных умеет сортировать; при серверной пагинации сортировка на клиенте переупорядочит одну страницу. `sortBy` — поле для составной ячейки.
- `mono` — скорости, координаты, IMEI, время; `strong` — опорная ячейка; `muted` — вторичная.
- `activeId` — строка под просмотром, получает вставную брендовую полосу.
- `footer` — обычно `DsPagination` или сводка выбора; `empty` — `DsEmptyState` внутри тела.
- При перезапросе строки остаются на месте под `DsSkeleton`.

**Не делайте:** фильтры в заголовке столбца; сортировку по вычисляемому, выбору или действиям.
